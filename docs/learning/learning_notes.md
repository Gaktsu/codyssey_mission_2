## 1. Python 기초

### 1.1 변수

**개념**
- 변수는 값에 붙이는 이름입니다. 값을 한 번 계산해 두고 이름으로 다시 쓰거나, 값의 의미를 이름으로 드러내기 위해 사용합니다.
- Python에는 진짜 상수가 없어서, 바꾸지 않을 값은 관례적으로 대문자 이름으로 씁니다.

**이 프로젝트에서**
- `src/input_utils.py:11` `text`: 사용자가 입력한 문자열을 공백 제거 후 담아 두고 여러 조건에서 반복 사용
- `src/input_utils.py:18` `value`: `text`를 정수로 바꾼 결과
- `src/quiz_game.py:54` `choice`: 사용자가 고른 메뉴 번호
- `src/quiz_game.py:38` `EXIT_CHOICE = 7`: "종료 메뉴 번호"라는 의미를 이름으로 드러낸 상수. 숫자 `7`을 여러 곳에 직접 쓰면 메뉴가 바뀔 때 전부 고쳐야 하지만, 상수는 한 곳만 고치면 됨

### 1.2 자료형: int, str, bool, list, dict

**개념**

| 자료형 | 의미 | 예 |
| --- | --- | --- |
| `int` | 정수 | `7`, `-1` |
| `str` | 문자열 | `"abc"`, `"7"` |
| `bool` | 참/거짓 | `True`, `False` |
| `list` | 순서가 있는 값 목록, 번호(인덱스)로 접근 | `["ls", "pwd", "cd", "mkdir"]` |
| `dict` | 키와 값의 쌍, 키로 접근 | `{"question": "...", "answer": 2}` |

- `"7"`(str)과 `7`(int)은 다른 값입니다. `"7" == 7`은 `False`입니다.

**이 프로젝트에서**
- **str → int 변환:** `input()`은 항상 `str`을 돌려줍니다. 그래서 `src/input_utils.py:18`에서 `int(text)`로 바꾼 뒤 범위를 비교합니다.
- **bool:** `text.isascii()`, `text.isdigit()`, `min_value <= value <= max_value`는 모두 `bool`을 돌려주며 `if` 조건에 바로 쓰입니다. `if not text`(`src/input_utils.py:12`)는 빈 문자열 `""`이 거짓으로 취급되는 성질을 이용합니다.
- **dict:** `src/quiz_game.py:43` `actions`는 메뉴 번호(int)를 키로, 실행할 메서드를 값으로 갖습니다. `actions[choice]()`로 번호에 맞는 기능을 찾아 실행하므로, 같은 일을 `if/elif`를 6번 나열하지 않고 처리합니다.
- **list:** 퀴즈의 선택지 4개(`choices`)와 퀴즈 목록(`quizzes`)을 저장할 때 사용 예정 (구현 후 위치 기입)

### 1.3 조건문: if / elif / else

**개념**
- 조건이 참일 때만 특정 코드를 실행합니다. `elif`는 앞 조건이 거짓일 때 다음 조건을 검사하고, `else`는 모든 조건이 거짓일 때 실행됩니다.

**이 프로젝트에서**
- `src/input_utils.py:12-21` `read_int`는 입력을 다음 순서로 검사합니다.
  1. 빈 입력인가?
  2. 번호 그대로의 숫자인가? (`"02"`, `"+2"`, `"abc"` 거부)
  3. 허용 범위 안인가?
- **검사 순서가 중요한 이유:** `int("abc")`는 `ValueError`를 일으킵니다. 숫자인지 먼저 확인한 뒤 `int()`를 호출하므로 이 오류가 생기지 않습니다.
- `"02"` 거부 방법: `str(int("02"))`는 `"2"`가 되어 원래 입력 `"02"`와 다르므로 거부합니다.
- 여기서는 `elif` 대신 "조건이 맞으면 안내 후 `continue`"를 반복했습니다. 각 검사가 실패하면 바로 다시 입력받는 구조라 이렇게 쓰면 들여쓰기가 깊어지지 않습니다.

### 1.4 반복문: for와 while

**개념**

| | `for` | `while` |
| --- | --- | --- |
| 반복 기준 | 정해진 목록의 각 항목 | 조건이 참인 동안 |
| 언제 쓰나 | 반복 횟수·대상이 정해져 있을 때 | 언제 끝날지 미리 모를 때 |

- `while True`는 무한 반복이며, 안에서 `return`이나 `break`로 빠져나옵니다. `continue`는 아래 코드를 건너뛰고 다음 반복으로 넘어갑니다.

**이 프로젝트에서**
- **while:** `src/input_utils.py:10` 재입력 루프. 사용자가 올바른 값을 언제 입력할지 모르므로 `while True` 후 올바른 값이 들어오면 `return`
- **while:** `src/quiz_game.py:52` 메뉴 루프. 사용자가 종료를 고를 때까지 반복
- **for:** 출제된 문제를 하나씩 푸는 부분에서 사용 예정 (구현 후 위치 기입)

### 1.5 함수: 정의, 매개변수, 반환값

**개념**
- 함수는 반복되는 작업에 이름을 붙여 묶은 것입니다. 매개변수로 값을 받고, `return`으로 결과를 돌려줍니다.

**이 프로젝트에서**
- `src/input_utils.py:4` `read_int(prompt, min_value, max_value)`
  - **매개변수:** 안내 문구, 최솟값, 최댓값
  - **반환값:** 검증을 통과한 `int`
- **함수로 만든 이유:** 메뉴(1~7), 정답(1~4), 모드 선택, 삭제 번호가 모두 "범위 안의 정수를 받을 때까지 묻기"라는 같은 작업입니다. 함수 하나를 매개변수만 바꿔 재사용하므로 검증 규칙을 한 곳에서만 관리합니다.
  - 예: `src/quiz_game.py:54` `read_int("메뉴 번호를 입력하세요: ", 1, EXIT_CHOICE)`
- **print와 return의 차이:** 오류 안내는 화면에 보여주기만 하면 되므로 `print`, 최종 입력값은 호출한 쪽에서 써야 하므로 `return`

## 2. 클래스와 객체

### 2.1 클래스란 무엇이고 왜 쓰는가

**개념**
- 클래스는 관련된 **데이터(속성)**와 **동작(메서드)**을 하나로 묶는 설계도이고, 그 설계도로 만든 실체가 객체(인스턴스)입니다.
- 묶어 두면 "이 데이터는 이 동작과 함께 다룬다"는 역할 구분이 코드 구조로 드러납니다.

**이 프로젝트에서**
- `QuizGame` (`src/quiz_game.py:41`): 메뉴 표시와 기능 실행 등 게임 전체 흐름을 담당
- `Quiz`: 문제 하나(질문, 선택지, 정답, 힌트)와 출력·정답 확인을 담당 (구현 후 작성)
- 두 클래스로 나눈 이유: *구현 후 작성*

### 2.2 `__init__`과 `self`

**개념**
- `__init__`은 객체를 만들 때 자동으로 호출되어 속성의 초기값을 정합니다.
- `self`는 "지금 메서드를 호출한 그 객체 자신"입니다. 메서드 안에서 `self.속성`, `self.메서드()`로 자기 데이터와 기능에 접근합니다.

**이 프로젝트에서**
- `src/quiz_game.py:44` `self.play_game`: `self`를 통해 같은 객체의 메서드를 꺼내 `actions` 딕셔너리에 담음. 괄호 없이 쓰면 "호출"이 아니라 "메서드 자체"를 값으로 다루는 것
- `__init__`: 현재 `QuizGame`은 저장할 속성이 아직 없어 `__init__`이 없음. 파일 불러오기 구현 시 `quizzes`, `best_scores`, `history`를 초기화하며 추가 예정 (구현 후 작성)
