# 학습 정리

미션 3장 "과제 목표"의 항목별 **개념**과 **사용 이유**를 정리합니다. 이 프로젝트에서 각 개념을 왜 그렇게 사용했는지는 소스 코드의 주석에 적습니다.

## 1. Python 기초

### 1.1 변수

**개념**
- 변수는 데이터를 저장하는 영역을 의미한다
- 이 영역에 저장된 데이터는 변경이 가능하다

**사용 이유**
- 여러곳에서 재사용이 가능하다
- 각 값에 의미를 부여할 수 있다
- 유지보수가 편리하다
- 값이 변경되었을때의 상태를 쉽게 추적할 수 있

### 1.2 자료형: int, str, bool, list, dict

**개념**

| 자료형 | 의미 | 예 |
| --- | --- | --- | 
| `int` | 정수 | `1`, `2` |
| `str` | 문자열 | `"abc"`, `"1"` | 
| `bool` | 참/거짓 | `True`, `False` | 
| `list` | 순서가 있는 값 목록 | `["ls", "pwd"]` | 
| `dict` | 키와 값의 쌍 | `{"answer": 1}` | 

```python
# str의 1과 int의 1은 다른 값임을 보여준다
>>> "1" == 1
False

# list는 여러 데이터들을 저장하며, 순서를 보장하는것을 보여준다
>>> l = ['a','b','c','d']
>>> l
['a', 'b', 'c', 'd']
>>> l[0]
'a'
>>> l[1]
'b'

# dict는 두 개의 값을 한 쌍으로 저장한다
# 순서를 보장하지 않으며, key값을 통해 value를 확인할 수 있음을 보여준다
>>> dict = {"banana":1, "apple":2, "grape":3}
>>> dict
{'banana': 1, 'apple': 2, 'grape': 3}
>>> dict[0]
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
KeyError: 0
>>> dict["banana"]
1
>>> dict["apple"]
2

# key값이 중복되면 덮어쓰는것을 보여준다
>>> dict["banana"] = 4
>>> dict["banana"]
4
```

### 1.3 조건문: if / elif / else

**개념**
- `if` 조건이 참이면 그 아래 코드를 실행합니다.
- `elif`는 앞의 조건이 모두 거짓일 때 다음 조건을 검사합니다.
- `else`는 모든 조건이 거짓일 때 실행됩니다.
- 위에서부터 차례로 검사하고, 처음으로 참인 블록 **하나만** 실행합니다.

```python
>>> score = 90
>>> if score >= 90:
...     grade = "A"
... elif score >= 80:
...     grade = "B"
... else:
...     grade = "C"
... 
>>> grade
'A'
```

**사용 이유**
- 값에 따라 프로그램이 다른 동작을 해야 할 때 사용한다

### 1.4 반복문: for와 while

**개념**

| | `for` | `while` |
| --- | --- | --- |
| 반복 기준 | list, dict등에서 데이터가 남아있는 동안 | 조건이 참인 동안 |
| 언제 쓰나 | 반복 대상·횟수가 정해져 있을 때 | 언제 끝날지 모를 때 |
| 예 | 리스트의 모든 문제 출력 | 올바른 값이 들어올 때까지 다시 입력받기 |

**사용 이유**
- 같은 작업을 여러 번 해야 할 때 코드를 반복해서 쓰지 않기 위해 사용합니다.
- 대상이 정해져 있으면 `for`가 범위를 벗어날 위험이 없어 안전하고, 종료 시점이 사용자 행동에 달려 있으면 `while`을 선택한다

### 1.5 함수: 정의, 매개변수, 반환값

**개념**
- `def 함수_이름(매개변수):`로 함수를 정의하고, `함수_이름(인자)`로 함수를 호출한다
- **매개변수**는 함수가 받는 입력이다
- **반환값**은 `return`으로 돌려주는 결과이다. 
  - `return`이 없으면 `None`을 돌려줍니다.

```python
>>> def add(a, b):
...     return a + b
... 
>>> result = add(2,3)
>>> result
5
```

## 2. 클래스와 객체

### 2.1 클래스란 무엇이고 왜 쓰는가

**개념**
- 클래스는 현실에 존재하는 것에서 필요한 정보만을 뽑아 상태와 행동을 정의한 설계도이다 
- 클래스로 만든 변수를 **객체(인스턴스)**라고 합니다. 하나의 클래스로 여러 객체를 만들 수 있고, 각 객체는 자기만의 값(상태)을 가집니다.

```python
>>> class Dog:
...     def __init__(self, name):
...         self.name = name
... 
>>> class Dog:
...     def __init__(self, name):
...         self.name = name
...     def bark(self):
...         print(f"{self.name}: 멍멍")
... 
>>> a = Dog("초코")
>>> a.bark()
초코: 멍멍
```

**사용 이유**
- 여러곳에서 재사용이 가능하다
- 관련 있는 데이터들을 묶어 하나의 데이터로 사용하고 관리하기 위함이다
- 동일 클래스를 기반으로 한 여러 객체들을 만들 수 있기 때문이다
- 다른 클래스와의 책임을 구분하고, 유지보수를 용이하게 하기 위함이다

### 2.2 `__init__`과 `self`

**개념**
- `__init__`은 객체를 만들 때 **자동으로 호출**되는 함수로, 속성의 초기값을 넣는다
- `self`는 "지금 이 메서드를 실행하는 객체 자신"을 가리킨다
  - 각 객체의 속성값은 독립적이지만, 함수는 같은 것을 사용한다
    - `self`가 없으면 함수는 어떤 객체가 자신을 호출했는지 알 수 없다
- 메서드를 정의할 때는 첫 매개변수로 `self`를 쓰지만, 호출할 때는 `a.bark()`처럼 생략합니다. Python이 `a`를 `self`로 자동 전달된다


### 2.3 속성과 메서드

**개념**
- **속성(attribute)**: 객체가 가진 데이터(변수 또는 상). Python에서 `self.이름 = 값`으로 만든다 외부에서는 `객체.이름`으로 사용한다
- **메서드(method)**: 클래스 안에 정의된 함수. 객체의 행동을 정의한다 

```python
>>> class Dog:
...     def __init__(self, name):
...         self.name = name # 속성 선언 및 초기화
...     def bark(self): # 메서드 정의
...         print(f"{self.name}: 멍멍")
... 
>>> a = Dog("초코")
>>> a.bark() # 메서드 호출
초코: 멍멍
>>> a.name # 속성 사용
'초코'
```

## 3. 파일 입출력과 예외 처리

### 3.1 파일 열기·읽기·쓰기

**개념**
- Python에서 `open(경로, 모드, encoding=...)`으로 파일을 엽니다.

| 모드 | 의미 |
| --- | --- |
| `"r"` | 읽기 (기본값). 파일이 없으면 `FileNotFoundError` |
| `"w"` | 쓰기. 파일이 없으면 만들고, **있으면 내용을 지우고** 새로 씀 |
| `"a"` | 이어 쓰기. 기존 내용 뒤에 추가 |

- `with open(...) as f:` 코드를 사용하면 블록가 끝날 때 파일이 **자동으로 닫힌다.**
- `encoding="..."`을 사용하지 않으면 운영체제 기본 인코딩을 사용하므로, Windows 등에서 한글이 깨질 수 있다.

```python
# UTF-8 인코딩으로 파일 쓰기 모드로 열기
>>> with open("memo.txt", "w", encoding="UTF-8") as f:
...     f.write("안녕하세요")
... 
5

# UTF-8 인코딩으로 파일 읽기 모드로 열기
# 인코딩이 같으므로 깨지지 않는것을 확인
>>> with open("memo.txt", "r", encoding="UTF-8") as f:
...     text = f.read()
... 
>>> text
'안녕하세요'

# latin1 인코딩으로 파일 읽기 모드로 열기
# 인코딩이 다르므로 깨지는 것을 확인 
>>> with open("memo.txt", "r", encoding="latin1") as f:
...     text = f.read()
... 
>>> text
'ì\x95\x88ë\x85\x95í\x95\x98ì\x84¸ì\x9a\x94'
```

### 3.3 try / except

**개념**
- 실행 중 오류(예외)가 발생할 수 있는 코드를 `try`에 넣고, 오류가 났을 때 할 일을 `except`에 쓴다
- `except (A, B):`처럼 여러 예외를 한 번에 잡을 수 있다
- `try`를 사용한 함수에 `except`가 없다면 자신을 호출한 함수로 계속 돌아가면서 찾는다 

```python
>>> try:
...     result = 10 / 0
... except ZeroDivisionError:
...     print("0으로 나눌 수 없습니다!")
... 
0으로 나눌 수 없습니다!
```

**사용 이유**
- 오류가 발생했을때 종료되는것을 막기 위해서이다

## 4. Git 기초

### 4.1 Git이 무엇이고 왜 필요한가

**개념**
- Git은 프로젝트 내에서 발생한 변경을 버전별로 기록하는 **분산 버전 관리 시스템**이다
- 변경 내용을 **커밋** 단위로 저장하며, 각 커밋에는 "누가, 언제, 무엇을, 왜" 바꿨는지가 남는다
- 작업 디렉터리 → 스테이징 영역(`add`) → 로컬 저장소(`commit`) → 원격 저장소(`push`) 순서로 변경이 이동한다
- GitHub는 Git의 로컬 저장소를 온라인에 올려 공유·협업할 수 있게 해 주는 플랫폼이다

**사용 이유**
- 이전 상태로 언제든 되돌릴 수 있습니다.
- 변경 이유와 과정이 기록으로 남습니다.
- 브랜치로 기능을 나눠 작업하면 main의 안정적인 코드를 건드리지 않고 개발할 수 있습니다.
- 여러 사람이 같은 프로젝트를 동시에 작업하고 합칠 수 있습니다.

### 4.2 명령어 7종

| 명령어 | 역할 |
| --- | --- |
| `git init` | 현재 폴더를 새 Git 저장소로 만듦 (`.git` 폴더 생성) |
| `git clone <URL>` | 원격 저장소 전체(이력 포함)를 로컬로 복제 |
| `git add <파일>` | 변경 내용을 다음 커밋에 포함하도록 스테이징 영역에 올림 |
| `git commit -m "메시지"` | 스테이징된 변경을 하나의 기록(커밋)으로 저장 |
| `git push` | 로컬 커밋을 원격 저장소에 업로드 |
| `git pull` | 원격 저장소의 새 커밋을 가져와 현재 브랜치에 합침 |
| `git checkout <브랜치>` | 다른 브랜치로 이동. `-b` 옵션을 붙이면 새 브랜치를 만들고 이동 |

### 4.3 브랜치 생성과 병합

**개념**
- 브랜치는 독립적인 작업 공간이다.
- 새 브랜치에서 한 커밋은 다른 브랜치에 영향을 주지 않는다.
- 병합(`merge`)은 두 브랜치를 합쳐 새로운 병합 커밋을 만든다.
![병합 커밋](../screenshot/병합%20커밋.png)

```bash
git checkout -b feature/quiz-play   # 브랜치 생성 후 이동
# ... 작업 후 add, commit ...
git checkout main                   # main으로 돌아옴
git merge feature/quiz-play         # 작업 내용을 main에 합침
```

- 두 브랜치가 같은 부분을 다르게 고쳤으면 **충돌(conflict)**이 난다
- 직접 내용을 골라 정리한 뒤 커밋해야 한다

**사용 이유**
- 기능 단위로 브랜치를 나누면 완성되지 않은 코드가 main에 섞이지 않습니다.
- 기능마다 변경 이력이 구분되어 어떤 기능이 언제 합쳐졌는지 추적하기 쉽습니다.
- 충돌내기 위해 추가한 내용

### 4.4 clone과 pull

**개념**
- `clone`은 원격 저장소를 **처음 한 번** 로컬로 가져오는 명령입니다. 원격 주소(`origin`)가 자동으로 등록됩니다.
- `pull`은 이미 clone한 저장소에서 원격의 **새로운 변경만** 가져와 합치는 명령입니다.

**사용 이유**
- 다른 컴퓨터나 다른 사람이 push한 변경을 내 로컬 저장소에 반영해, 모두가 최신 상태에서 작업할 수 있게 합니다.
- 작업 전에 `pull`로 최신 상태를 받아 두면 충돌을 줄일 수 있습니다.
