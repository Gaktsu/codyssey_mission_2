# 요구사항 분석 및 프로그램 설계

> 상태: 초기 설계안 (실제 구현 내용과 다른 경우 검증 후 갱신)

## 1. 요구사항 분석

### 1.1 기능 요구사항

| ID | 기능 | 요구사항 |
| --- | --- | --- |
| FR-01 | 메뉴 | 1~7번 선택, 잘못된 입력 재요청, 종료 |
| FR-02 | 퀴즈 풀기 | 저장된 퀴즈 출제 및 정답/오답 판정 |
| FR-03 | 랜덤 출제 | 중복 없이 무작위 출제 |
| FR-04 | 문제 수 선택 | 10 / 20 / 30문제 중 선택, 등록된 문제 수가 부족한 모드는 안내 후 재선택 |
| FR-05 | 힌트 | 문제당 최대 1회, 힌트 사용 정답 시 점수 차감 |
| FR-06 | 퀴즈 추가 | 질문·보기 4개·정답 1~4·힌트 입력 후 저장 |
| FR-07 | 퀴즈 목록 | 등록 퀴즈 목록 조회 및 빈 목록 처리 |
| FR-08 | 퀴즈 삭제 | 목록 번호 기준 삭제 및 저장, 취소 처리 |
| FR-09 | 최고 점수 | 문제 수(10/20/30)별로 기존 최고점과 비교 후 갱신, 게임 종료 후 입력한 이니셜과 함께 저장 |
| FR-10 | 점수 히스토리 | 완료 시 모드별로 날짜·이니셜·푼 문제 수·점수 기록 (모드별 최근 10개만 보관) |
| FR-11 | 데이터 영속성 | 퀴즈와 점수 데이터를 JSON으로 유지 |
| FR-12 | 예외 처리 | 입력 오류, JSON 누락·손상, 입출력 오류, 안전 종료 |

기본 퀴즈는 Linux 10개, Docker 10개, Git 10개로 **총 30개**를 작성합니다. 첫 실행부터 10/20/30문제 모드를 모두 플레이할 수 있도록 하기 위함입니다.

### 1.2 비기능 요구사항

- Python 3.10 이상, 표준 라이브러리만 사용
- 최소 `Quiz`, `QuizGame` 두 클래스 사용
- 데이터 파일 UTF-8 저장, 한글 가독성을 위해 `ensure_ascii=False` 사용
- 기능 단위 의미 있는 Git 커밋 최소 10개 및 브랜치 병합 기록
- `git init`, `add`, `commit`, `push`, `pull`, `checkout`, `clone` 실습
- 잘못된 입력에도 메뉴로 돌아가거나 안전하게 종료하도록 설계

### 1.3 제약사항과 평가 확인 사항

- Python 코드: `src/` 패키지
- JSON 파일: `data/state.json`(퀴즈), `data/scores.json`(점수)
- **과제 원문과 차이(의도된 설계):** 미션 원문은 루트 `state.json` 단일 파일에 퀴즈와 최고 점수를 저장하도록 되어 있습니다. 이 프로젝트는 성격이 다른 데이터를 한 파일에 섞지 않기 위해 **의도적으로 2개 파일로 분리**합니다.
  - `state.json`: 문제 콘텐츠. 사용자가 추가·삭제할 때만 바뀌는 데이터
  - `scores.json`: 플레이 결과. 게임을 할 때마다 쌓이는 데이터
  - 분리하면 한쪽 파일이 손상되어 초기화되더라도 다른 쪽 데이터(예: 직접 추가한 퀴즈)는 유지됨
- 사용자 입력·파일 내용 모두 검증 대상으로 간주

## 2. 프로그램 구조

### 2.1 전체 프로그램 구성

프로젝트 루트에서 `python -m src.main`으로 실행하는 콘솔 프로그램입니다. 입력 처리, 개별 문제, 게임 전체 관리, 초기 데이터 역할을 분리합니다.

### 2.2 파일별 역할

| 파일 | 책임 |
| --- | --- |
| `src/main.py` | 진입점, 게임 시작, 최상위 중단 처리 |
| `src/quiz.py` | `Quiz` 객체의 출력·정답 판정·직렬화 |
| `src/quiz_game.py` | 메뉴, 게임 진행, 추가·삭제, 점수, 로드·저장 |
| `src/input_utils.py` | 공통 입력 정제·범위 검증 |
| `src/default_quizzes.py` | 기본 퀴즈 30개 데이터 생성 |
| `data/state.json` | 퀴즈 데이터 |
| `data/scores.json` | 모드별 최고 점수·플레이 기록 |

### 2.3 프로그램 실행 흐름

1. 시작 시 JSON 두 파일을 **각각** 읽고 검증 (처리 규칙은 6.2 참고)
2. 메뉴 표시: `1. 퀴즈 풀기 / 2. 퀴즈 추가 / 3. 퀴즈 목록 / 4. 퀴즈 삭제 / 5. 최고 점수 / 6. 점수 기록 / 7. 종료`
3. 선택 기능 실행 후 메뉴로 복귀
4. 데이터가 바뀌는 시점(퀴즈 추가, 퀴즈 삭제, 게임 완료)마다 **즉시** 해당 JSON 파일 저장
5. 7번 종료 또는 어느 화면에서든 입력 중단(Ctrl+C / EOF) 시 안내 메시지 출력 후 종료 (저장할 데이터가 남아 있지 않음)

## 3. 클래스 설계

### 3.1 Quiz 클래스 (`src/quiz.py`)

- 속성: `question: str`, `choices: list[str]` (4개), `answer: int` (1~4), `hint: str`
- 메서드: `display(number)`(문제 출력), `check_answer(selected)`(정답 여부 반환), `to_dict()`(JSON 저장용 dict 변환), `from_dict(data)`(dict로 객체 생성, `@classmethod`)
- 데이터 유효성 검사: `__init__`에서 빈 질문/선택지/힌트, 4개가 아닌 선택지, 범위 밖 정답을 `ValueError`로 거부
- 힌트 출력과 힌트 사용 여부 기록은 퀴즈 풀기(`QuizGame`)에서 처리

### 3.2 QuizGame 클래스 (`src/quiz_game.py`)

- 속성: `quizzes`(Quiz 객체 목록), `records`(모드별 최고 점수와 기록)
- 메서드: `run()`, `play_game()`, `add_quiz()`, `list_quizzes()`, `delete_quiz()`, `show_score()`, `show_history()`, `load_quizzes()`, `save_quizzes()`, `load_scores()`, `save_scores()`, `write_json()`
- 게임 중 임시 상태: 이번 게임의 출제 문제 수, 정답 수, 힌트 사용 수, 힌트 사용 후 정답 수
- 실제 구현 중 메서드는 하위 메서드로 더 나눌 수 있음

### 3.3 클래스 간 관계

`QuizGame`이 여러 `Quiz` 인스턴스의 목록을 보유하고 게임 진행을 관리하는 **일대다 보유 관계**입니다. 객체 생성·소유권 정책을 구현하기 전에는 엄격한 합성(Composition) 관계로 단정하지 않습니다.

## 4. 데이터 설계

### 4.1 퀴즈 데이터 구조

- 필드: `question`, `choices`, `answer`, `hint`
- 별도 ID는 두지 않고, 목록·삭제 화면에서는 리스트 순서대로 매긴 번호(1부터)를 사용
- 퀴즈가 하나도 없는 `"quizzes": []`는 **정상 상태**로 취급 (전부 삭제 후 재실행해도 기본 문제를 되살리지 않음)

### 4.2 점수 관리

- 게임 모드: **10 / 20 / 30문제** 고정
- 모든 정답 문항은 기본 100점, 힌트를 사용하고 정답인 문항은 90점, 오답은 0점
- 최종 점수: `(정답 수 × 100 - 힌트 사용 후 정답 문항 수 × 10) // 출제 문제 수`
  - 정수 나눗셈(`//`)으로 소수점 아래는 버림 (예: 22.5 → 22). 미션에 실수 사용 요구가 없음
- 최고 점수는 **모드별로 따로** 관리: `null`(해당 모드 미플레이) 또는 `{"name": 이니셜, "score": 0~100}`
- 게임이 끝나면 이니셜을 입력받아 최고 점수와 기록에 함께 저장
- 기록(`scores`)은 모드별로 날짜, 이니셜, 푼 문제 수, 점수를 저장하며 **최근 10개까지만** 보관
- 힌트 사용 후 오답일 때는 추가 감점 없음

### 4.3 JSON 스키마

`data/state.json`:

```json
{
  "quizzes": [
    {
      "question": "현재 경로를 출력하는 Linux 명령어는?",
      "choices": ["ls", "pwd", "cd", "mkdir"],
      "answer": 2,
      "hint": "현재 작업 중인 위치를 출력하는 명령어입니다."
    }
  ]
}
```

`data/scores.json`:

```json
{
  "mode": {
    "10": {
      "best_score": {"name": "KMS", "score": 95},
      "scores": [
        {"date": "2026-11-12 14:30:00", "name": "KMS", "total_questions": 10, "score": 95}
      ]
    },
    "20": {"best_score": null, "scores": []},
    "30": {"best_score": null, "scores": []}
  }
}
```

> 위 `state.json` 예시는 구조를 보여주기 위해 1문제만 표시했습니다.
>
> JSON 객체의 키는 문자열만 가능하므로 모드 키는 `"10"`처럼 문자열로 저장합니다.
>
> `state.json`과 `scores.json` 모두 저장소에 포함합니다. `state.json`에는 기본 퀴즈 30개가 들어 있습니다.

## 5. 주요 기능 설계

### 5.1 메뉴 및 입력 처리

- `while` 루프로 1~7 메뉴 반복, 7번은 확인 없이 안내 후 종료
- 공통 입력 함수 `read_int(prompt, min_value, max_value)`를 메뉴·정답·모드·삭제 번호 입력에 재사용
- 입력값의 앞뒤 공백만 제거하고, **번호 그대로의 ASCII 숫자만 인정** (`02`, `+2`, `1_0`, `1.0`, 전각·아랍 숫자 등은 거부)
- 오류 메시지는 빈 입력 / 숫자 아님 / 범위 밖 세 가지로 구분하며, 메뉴 전체가 아닌 입력 줄만 다시 요청
- 모드 선택처럼 연속 범위가 아닌 선택지는 `1. 10문제 / 2. 20문제 / 3. 30문제 / 0. 돌아가기`처럼 번호로 제시
- 아직 구현되지 않은 메뉴는 "준비 중입니다" 안내 후 메뉴로 복귀

### 5.2 퀴즈 풀기

- 퀴즈가 0개면 모드를 묻지 않고 안내 후 메뉴로 복귀
- 모드 선택(`1. 10문제 / 2. 20문제 / 3. 30문제 / 0. 돌아가기`), `random.sample()`로 중복 없이 출제
- 등록된 퀴즈 수가 선택한 모드의 문제 수보다 적으면 안내 후 다시 선택
- 정답 입력 `1~4`, **`0`을 입력하면 힌트** 표시
  - 같은 문제에서 다시 `0`을 입력하면 "이미 힌트를 사용했습니다" 안내 후 힌트를 다시 보여줌 (감점은 한 번만)
- 정답이면 `✅ 정답입니다!`, 오답이면 `❌ 오답입니다. 정답: 번호. 내용`
- 모두 완료하면 정답 수·힌트 사용 수·점수 표시 → 이니셜 입력(영문 1~3자, 대문자로 저장) → 해당 모드 최고 점수 비교 → 기록 추가(최근 10개 유지) 및 저장
- 최고 점수를 넘었으면 `🎉 새로운 최고 점수입니다!` 표시
- 게임 진행 중에는 저장하지 않으며, 중간에 중단된 게임은 기록하지 않음

### 5.3 퀴즈 추가

- 질문, 선택지 4개, 정답 번호(1~4), 힌트 입력
- 빈 값(공백만 입력 포함)은 재입력, 정답 번호는 `read_int`로 검증
- 퀴즈 목록 끝에 추가하고 저장, 성공 시 `✅ 퀴즈가 추가되었습니다! (총 N개)`
- 저장 실패 시 실패 안내와 함께 "프로그램을 종료하면 사라진다"고 알림

### 5.4 퀴즈 목록 조회

- `📋 등록된 퀴즈 목록 (총 N개)` 아래에 `[번호] 질문`, 다음 줄에 선택지를 ` / `로 구분해 출력
- 번호는 리스트 순서대로 1부터 매기며, 퀴즈 삭제에서도 같은 번호를 사용
- 등록 문제가 없으면 안내
- **정답은 표시하지 않음** (플레이 전 노출 방지)

### 5.5 퀴즈 삭제

- 목록 출력 → 삭제할 번호 입력(1~퀴즈 수, `0`은 취소) → 삭제 확인(`y`/`n`) → 퀴즈 리스트에서 제거 → 저장
- 확인 입력이 `y`/`n`이 아니면 **재입력** 요청
- 등록된 퀴즈가 없으면 안내 후 메뉴로 복귀

### 5.6 최고 점수 확인

- 10 / 20 / 30문제 모드별 최고 점수와 이니셜 표시, 값이 `null`인 모드는 "기록 없음"으로 표시
- 기존 기록 초과 시에만 갱신; 동점 시 유지

### 5.7 점수 기록 히스토리

- 게임 완료마다 해당 모드에 현지 날짜/시간, 이니셜, 푼 문제 수, 점수 저장
- 모드별 최근 10개만 보관 (11번째부터는 가장 오래된 기록 삭제)
- 기록이 없을 때 안내, 재실행 후 기록 유지

### 5.8 저장 및 불러오기

- `json`과 `pathlib` 사용; 실행 위치와 무관하게 프로젝트 루트 기준 파일 경로 계산
- 파일별 로드·검증·예외 처리 독립 수행
- UTF-8과 `ensure_ascii=False`, `indent=2` 사용
- 저장 실패(`OSError`) 시 실패했다고 안내하며, 성공한 것처럼 표시하지 않음

## 6. 예외 처리 설계

### 6.1 잘못된 사용자 입력

- 메뉴 `abc`, `0`, `9`, 공백/빈 입력 처리
- 정답 `0`, `5`, 문자, 빈 입력 처리
- 퀴즈 추가 시 빈 질문/선택지/힌트 및 비정상 데이터 거부
- 모드 번호 범위 밖, 비숫자 처리

### 6.2 파일 누락 및 손상

파일을 읽을 때 오류 종류에 따라 다르게 처리합니다. 한 파일의 처리가 다른 파일의 데이터를 바꾸지 않습니다.

| 상황 | 판단 | 처리 |
| --- | --- | --- |
| 상황 | `state.json` (퀴즈) | `scores.json` (점수) |
| --- | --- | --- |
| 파일 없음 (`FileNotFoundError`) | 안내 후 기본 퀴즈 30개로 시작, **파일은 쓰지 않음** | 안내 후 빈 기록으로 **새로 만듦** |
| JSON 문법 오류 (`JSONDecodeError`) | 안내 후 기본 퀴즈로 시작, **덮어쓰지 않음** | 안내 후 빈 기록으로 초기화해 저장 |
| 파일 구조·내용 오류 | 안내 후 기본 퀴즈로 시작, **덮어쓰지 않음** | 안내 후 빈 기록으로 초기화해 저장 |
| 읽기 권한·입출력 오류 (`OSError`) | 안내 후 기본 퀴즈로 시작, 덮어쓰지 않음 | 안내 후 이번 실행만 빈 기록 사용, 덮어쓰지 않음 |

- `state.json`은 사용자가 넣은 문제가 들어 있는 파일이라 시작할 때 덮어쓰지 않습니다. 기본 퀴즈는 메모리에서만 쓰다가, 퀴즈를 추가·삭제하면 그때 현재 목록으로 저장됩니다.
- **`state.json` 구조·내용 오류:** 최상위가 객체가 아님, `quizzes` 목록 없음, 퀴즈 항목 중 하나라도 잘못됨(질문·선택지·힌트가 비어 있음, 선택지가 4개가 아님, 정답이 1~4 범위 밖, 필수 키 누락)
- **`scores.json` 구조·내용 오류:** `mode` 또는 `"10"`/`"20"`/`"30"` 모드 항목 없음, 그리고 다음 중 하나라도 해당
  - 최고 점수: `null`이 아닌데 이니셜이 비어 있거나 점수가 0~100 정수가 아님
  - 기록: 날짜가 `YYYY-MM-DD HH:MM:SS` 형식이 아님, 이니셜이 비어 있음, 푼 문제 수가 0 미만, 점수가 0~100 정수가 아님

### 6.3 프로그램 중단 및 안전 종료

- 어느 화면에서든 `KeyboardInterrupt` 또는 `EOFError` 발생 시 안내 메시지 출력 후 프로그램 종료 (`main.py` 한 곳에서 처리)
- 데이터는 변경 시점마다 즉시 저장되므로 종료 시점에 따로 저장할 내용이 없음
- 게임 중 중단 시 미완료 판은 기록하지 않음 (**완료된 게임만 저장**)
