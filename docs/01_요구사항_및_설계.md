# 요구사항 분석 및 프로그램 설계

> 상태: 초기 설계안 (실제 구현 내용과 다른 경우 검증 후 갱신)

## 1. 요구사항 분석

### 1.1 기능 요구사항

| ID | 기능 | 요구사항 |
| --- | --- | --- |
| FR-01 | 메뉴 | 1~7번 선택, 잘못된 입력 재요청, 종료 |
| FR-02 | 퀴즈 풀기 | 저장된 퀴즈 출제 및 정답/오답 판정 |
| FR-03 | 랜덤 출제 | 중복 없이 무작위 출제 |
| FR-04 | 문제 수 선택 | 1~등록된 문제 수 범위의 개수 선택 |
| FR-05 | 힌트 | 문제당 최대 1회, 힌트 사용 정답 시 점수 차감 |
| FR-06 | 퀴즈 추가 | 질문·보기 4개·정답 1~4·힌트 입력 후 저장 |
| FR-07 | 퀴즈 목록 | 등록 퀴즈 목록 조회 및 빈 목록 처리 |
| FR-08 | 퀴즈 삭제 | ID 기준 삭제 및 저장, 취소 처리 |
| FR-09 | 최고 점수 | 기존 최고점과 비교 후 갱신 |
| FR-10 | 점수 히스토리 | 완료 시 날짜·문제 수·정답 수·힌트 수·점수 누적 기록 |
| FR-11 | 데이터 영속성 | 퀴즈와 점수 데이터를 JSON으로 유지 |
| FR-12 | 예외 처리 | 입력 오류, JSON 누락·손상, 입출력 오류, 안전 종료 |

기본 퀴즈는 Linux 2개, Docker 2개, Git 2개로 **총 6개**를 작성합니다.

### 1.2 비기능 요구사항

- Python 3.10 이상, 표준 라이브러리만 사용
- 최소 `Quiz`, `QuizGame` 두 클래스 사용
- 데이터 파일 UTF-8 저장, 한글 가독성을 위해 `ensure_ascii=False` 사용
- 기능 단위 의미 있는 Git 커밋 최소 10개 및 브랜치 병합 기록
- `git init`, `add`, `commit`, `push`, `pull`, `checkout`, `clone` 실습
- 잘못된 입력에도 메뉴로 돌아가거나 안전하게 종료하도록 설계

### 1.3 제약사항과 평가 확인 사항

- Python 코드: `src/` 패키지
- JSON 파일: `data/state.json`(퀴즈), `data/scores.json`(점수)
- **과제 원문과 차이:** 미션은 **루트 `state.json` 단일 파일에 퀴즈와 최고 점수를 저장**하도록 요구합니다. 현재 2파일 분리 설계는 명시 조건을 그대로 준수하지 않으므로, 평가 전 허용 여부 확인이 필요합니다. 승인되지 않으면 파일 위치 및 필수 데이터 구조를 변경합니다.
- 사용자 입력·퀴즈 데이터·파일 내용 모두 검증 대상으로 간주

## 2. 프로그램 구조

### 2.1 전체 프로그램 구성

프로젝트 루트에서 `python -m src.main`으로 실행하는 콘솔 프로그램입니다. 입력 처리, 개별 문제, 게임 전체 관리, 초기 데이터 역할을 분리합니다.

### 2.2 파일별 역할

| 파일 | 책임 |
| --- | --- |
| `src/main.py` | 진입점, 게임 시작, 최상위 중단 처리 |
| `src/quiz.py` | `Quiz` 객체의 출력·정답 판정·직렬화 |
| `src/quiz_game.py` | 메뉴, 게임 진행, 추가·삭제, 점수, 로드·저장 |
| `src/input_utils.py` | 공통 입력 정제·범위 검증 |
| `src/default_quizzes.py` | 기본 퀴즈 6개 데이터 생성 |
| `data/state.json` | 퀴즈 데이터 |
| `data/scores.json` | 최고 점수·플레이 히스토리 |
| `tests/` | `unittest` 기반 기능·저장·예외 테스트 |

### 2.3 프로그램 실행 흐름

1. 시작 시 JSON 두 파일을 **각각** 읽고 검증; 없거나 손상된 파일만 초기화 시도
2. 메뉴 표시: `1. 퀴즈 풀기 / 2. 퀴즈 추가 / 3. 퀴즈 목록 / 4. 퀴즈 삭제 / 5. 최고 점수 / 6. 점수 기록 / 7. 종료`
3. 선택 기능 실행 후 메뉴로 복귀
4. 데이터 변경 시 해당 JSON 파일 저장
5. 종료 또는 입력 중단 시 가능한 범위에서 저장 후 종료

## 3. 클래스 설계

### 3.1 Quiz 클래스 (`src/quiz.py`)

- 속성: `id: int`, `question: str`, `choices: list[str]` (4개), `answer: int` (1~4), `hint: str`
- 예정 메서드: `display()`, `check_answer(selected)`, `show_hint()`, `to_dict()`
- 데이터 유효성 검사: 빈 질문/선택지/힌트, 4개가 아닌 선택지, 범위 밖 정답 거부
- JSON 로드 시 딕셔너리에서 Quiz 객체 복원하는 기능 필요(`from_dict()` 등)

### 3.2 QuizGame 클래스 (`src/quiz_game.py`)

- 속성: `quizzes`, `best_score`, `history`
- 예정 메서드: `run()`, `play_game()`, `add_quiz()`, `list_quizzes()`, `delete_quiz()`, `show_score()`, `show_history()`, `load_quizzes()`, `save_quizzes()`, `load_scores()`, `save_scores()`
- 게임 중 임시 상태: 이번 게임의 출제 문제 수, 정답 수, 힌트 사용 수, 힌트 사용 후 정답 수
- 실제 구현 중 메서드는 하위 메서드로 더 나눌 수 있음

### 3.3 클래스 간 관계

`QuizGame`이 여러 `Quiz` 인스턴스의 목록을 보유하고 게임 진행을 관리하는 **일대다 보유 관계**입니다. 객체 생성·소유권 정책을 구현하기 전에는 엄격한 합성(Composition) 관계로 단정하지 않습니다.

## 4. 데이터 설계

### 4.1 퀴즈 데이터 구조

- 문제마다 고유 ID 부여(삭제 및 식별 목적)
- 필드: `id`, `question`, `choices`, `answer`, `hint`
- 신규 ID가 삭제로 재사용되지 않도록 `next_id`를 함께 저장하는 방식 사용 권장

### 4.2 점수 관리

- 모든 정답 문항은 기본 100점, 힌트를 사용하고 정답인 문항은 90점, 오답은 0점
- 최종 점수: `round((정답 수 × 100 - 힌트 사용 후 정답 문항 수 × 10) / 출제 문제 수)`
- 출제 문제 수가 0이면 점수 계산을 하지 않고 메뉴로 복귀
- 최고 점수: `null`(미플레이) 또는 정수 0~100
- 히스토리에는 문제 수, 정답 수, 전체 힌트 사용 수, 최종 점수를 저장
- 힌트 사용 후 오답일 때는 추가 감점 없음

### 4.3 JSON 스키마

`data/state.json`:

```json
{
  "next_id": 7,
  "quizzes": [
    {
      "id": 1,
      "question": "현재 경로를 출력하는 Linux 명령어는?",
      "choices": ["ls", "pwd", "cd", "mkdir"],
      "answer": 2,
      "hint": "현재 작업 중인 위치를 출력하는 명령어입니다."
    }
  ]
}
```

`data/scores.json`:

```json
{
  "best_score": null,
  "history": []
}
```

> `next_id`는 새 문제 ID 발급용이며, 기본 퀴즈 6개를 넣은 초기 상태에서는 7부터 발급합니다. 위 `state.json` 예시는 구조를 보여주기 위해 1문제만 표시했습니다.

## 5. 주요 기능 설계

### 5.1 메뉴 및 입력 처리

- `while` 루프로 1~7 메뉴 반복
- 입력값의 앞뒤 공백 제거 후 빈 문자열 검사, 정수 변환 및 범위 검사
- 오류일 경우 안내 및 재입력; `KeyboardInterrupt`·`EOFError`는 상위 종료 흐름에 전달

### 5.2 퀴즈 풀기

- 문제 수 선택(1~현재 퀴즈 수), `random.sample()`로 중복 없이 출제
- 사용자에게 정답 입력 또는 힌트 요청 선택 제공
- 문제별 정답/오답 판정, 힌트 사용 여부 기록
- 모두 완료하면 최종 점수 계산, 최고 점수 비교, 히스토리 기록 및 저장
- 문제 0개면 안내 후 메뉴로 이동

### 5.3 퀴즈 추가

- 질문, 선택지 4개, 정답 번호(1~4), 힌트 입력
- 잘못된 입력 재요청 후 고유 ID 부여
- `data/state.json` 저장에 성공했는지 확인

### 5.4 퀴즈 목록 조회

- 문제 ID와 질문, 선택지 출력; 등록 문제가 없으면 안내
- 정답 공개 여부는 구현 시 결정(플레이 전 노출 방지 고려)

### 5.5 퀴즈 삭제

- 삭제할 문제 ID 확인 → 사용자 확인 → 퀴즈 리스트에서 제거 → 저장
- 존재하지 않는 ID, 취소, 마지막 퀴즈 삭제 후 빈 목록 처리

### 5.6 최고 점수 확인

- `best_score`가 `null`이면 플레이 기록이 없다고 표시
- 기존 기록 초과 시에만 갱신; 동점 시 유지

### 5.7 점수 기록 히스토리

- 게임 완료마다 현지 날짜/시간, 출제 문제 수, 정답 수, 힌트 사용 수, 점수 저장
- 기록이 없을 때 안내, 재실행 후 기록 유지

### 5.8 저장 및 불러오기

- `json`과 `pathlib` 사용; 실행 위치와 무관하게 프로젝트 루트 기준 파일 경로 계산
- 파일별 로드·검증·예외 처리 독립 수행
- UTF-8과 `ensure_ascii=False`, `indent=2` 사용
- 저장 중 오류로 기존 파일이 훼손되지 않도록 임시 파일 기록 후 교체 방식 고려

## 6. 예외 처리 설계

### 6.1 잘못된 사용자 입력

- 메뉴 `abc`, `0`, `9`, 공백/빈 입력 처리
- 정답 `0`, `5`, 문자, 빈 입력 처리
- 퀴즈 추가 시 빈 질문/선택지/힌트 및 비정상 데이터 거부
- 문제 수 `0`, 현재 문제 수 초과, 비숫자 처리

### 6.2 파일 누락 및 손상

- `data/state.json` 누락/JSON 파싱 실패/스키마 오류: 기본 6문제로 복구 시도
- `data/scores.json` 누락/JSON 파싱 실패/스키마 오류: `best_score=null`, `history=[]`로 복구 시도
- 한 파일 복구가 다른 파일 데이터를 변경하지 않도록 함
- 읽기/쓰기 권한 오류 등은 안내하고 안전하게 처리

### 6.3 프로그램 중단 및 안전 종료

- `KeyboardInterrupt` 또는 `EOFError`: 사용자에게 안내 후 저장 가능한 데이터 저장 시도 및 종료
- 저장 자체가 실패한 경우 오류를 고지하며, 저장 성공으로 표시하지 않음
- 게임 중 중단 시 미완료 판의 히스토리 처리 여부는 **완료된 게임만 저장**하는 것으로 고정
